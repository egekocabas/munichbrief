# Licences, credits and model review

Last checked: **14 September 2026**. This implements the licence additions to
[PR #67](https://github.com/egekocabas/munichbrief/pull/67). It does not select,
qualify, download, remove or deploy models. See [the continuation notes](continuation-notes.md)
for the separate provider/legal correspondence.

## Inventory and distributed material

The single reviewed source is [manifest.json](../internal/licensing/manifest.json).
It records exact dependency versions, asset hashes, original notice files, review
dates, distribution locations and model provenance. It currently covers 54
components and 55 distinct notice texts. Original copyright statements remain in
the full texts; identical permission texts are deduplicated without merging the
component attributions.

[THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) and the embedded JSON bundle
are generated by [scripts/licenses.mjs](../scripts/licenses.mjs). The public SSR
and Markdown credits, protected model overview and offline CLI consume that
bundle. `munichbrief licenses` works before configuration and database startup.
The final container carries the readable bundle under `/usr/share/munichbrief/`,
including `LICENSES/` and exact corresponding source archives for base-files,
netbase and ca-certificates. Debian's existing `/usr/share/doc/*/copyright` and
`/usr/share/common-licenses` remain intact. The MIT image label identifies the
project code; it does not relicense the container's other material.

Coverage includes both Linux architectures' linked direct/indirect Go modules,
Go runtime and standard-library vendored code, modernc's embedded C/SQLite notices,
HarfBuzz shaping code, browser HTMX and head support, generated Tailwind CSS, Noto
and Go fonts, project assets, the modified EU AI icon and geographic sources.
Build tools are distinguished from code actually included in release artefacts.
Optional BoringCrypto and compiler-only Go dependencies are not linked by the
supported CGO-disabled build. The inference server and model weights are separately
installed; the application image does not contain them.

The pinned distroless image contains base-files 12.4+deb12u15,
ca-certificates 20250419~deb12u1, media-types 10.0.0, netbase 6.4 and
tzdata 2026b-0+deb12u1. The copied builder timezone data is also checked by hash.
Debian source tarballs were checked against their source descriptor's SHA-256;
this is integrity verification, not a claim of independent signing-key validation.

The European Commission's **specific icon permission** allows free use without
Commission/AI Office attribution. It distinguishes use from Code signatory status.
Do not replace this with an assumed generic CC BY licence. The original permission
and our light-variant modification notice are included. [Official icon guidance](https://digital-strategy.ec.europa.eu/en/policies/eu-icons-labelling-ai-generated-content).
The head-support npm package declares 0BSD but supplies no separate LICENSE file;
its package declaration and the 0BSD permission text are preserved without inventing
a copyright holder. Original font names and licence texts are unchanged.

Geographic attribution is consistent with About: Landeshauptstadt München –
GeodatenService (dl-de/by-2.0), GeoNames (CC BY 4.0), and © OpenStreetMap
contributors (ODbL 1.0). Public copy identifies filtering and normalization. These
notices do not replace the [gazetteer source policy](gazetteer.md) or grant rights
to police releases. Police source material is expressly outside the project's MIT
licence. Any future distribution of a derived geographic database needs its own
ODbL source/share-alike assessment.

### Requirements and evidence

The application internally generates public summaries/translations, without a
public inference endpoint or distributed model weights. Apache 2.0 redistribution
conditions include the licence, retained copyright and relevant NOTICE information,
and identifying modifications. Do not invent an upstream NOTICE when none is
provided. Those conditions must be revisited if weights are packaged. Academic
citation requests are separate from mandatory licence attribution.

- [Hy-MT2 licence](https://github.com/Tencent-Hunyuan/Hy-MT2/blob/main/LICENSE.txt),
  [Qwen3.5 4B](https://huggingface.co/Qwen/Qwen3.5-4B),
  [Qwen3.5 9B](https://huggingface.co/Qwen/Qwen3.5-9B),
  [Gemma 4 Apache terms](https://ai.google.dev/gemma/apache_2),
  [EuroLLM](https://huggingface.co/utter-project/EuroLLM-9B-Instruct-2512),
  [MADLAD400](https://huggingface.co/google/madlad400-7b-mt),
  [Granite](https://huggingface.co/ibm-granite/granite-4.1-3b).
- [Gemma terms](https://ai.google.dev/gemma/terms): usage restrictions continue
  during internal use. The agreement distinguishes outputs from model derivatives;
  it includes hosted model access in distribution. Publishing a stored generated
  summary is not automatically weight redistribution. Check the prohibited-use
  restrictions and pass-through conditions before offering access or derivatives.
- [LLaMAX card](https://huggingface.co/LLaMAX/LLaMAX3-8B-Alpaca) and
  [Meta Llama 3 licence](https://github.com/meta-llama/llama3/blob/main/LICENSE):
  preserve the agreement, required attribution/branding and Acceptable Use Policy;
  observe applicable naming, scale and restrictions on using outputs to improve
  other LLMs. The present workflow is inference, not training another model. A
  claim of MIT alone would omit the inherited conditions.
- [TowerInstruct card](https://huggingface.co/Unbabel/TowerInstruct-7B-v0.2):
  noncommercial restrictions and Llama 2 conditions remain relevant even when
  no weights are distributed. No advertisements does not itself settle eligibility.
- [Tower-Plus card](https://huggingface.co/Unbabel/Tower-Plus-9B): retain the exact
  NC-SA/NC inconsistency and inherited Gemma restrictions. Until clarified, this
  record cannot establish permitted use. Both conflicting CC texts are retained;
  they are not presented as alternative permissions to choose between.

The public model references exclude unresolved/excluded entries and explicitly
say they are not a live deployment list. Article-level AI provenance remains.
Public references preserve required original legal phrases and full texts.
Private operational conditions are not rendered on the public credits page.

## Admin behaviour and review maintenance

`/admin/licenses` uses the existing protected admin boundary and cached catalogue.
The catalogue now retains a copy-isolated digest map; absent digests do not make
an otherwise available model unavailable for processing. A changed digest yields
**Artefact changed**; unknown/missing metadata yields **Review needed**; failed
catalogue refresh yields **Catalogue unavailable**, never a stale reviewed label.
Selected models appear first, with warnings ahead of reviewed entries. Model
settings also link to the overview and show concise warnings. No migration,
blocking licence gate, admin approval button or inference request was added.

To review a dependency or asset change:

1. Inspect its actual release contents and upstream terms, including embedded
   third-party code and NOTICE files. Update manifest entries, original texts and
   integrity hashes. Record the exact revision and review date.
2. For base images, inspect both architecture manifests and package contents,
   preserve upstream notices and provide corresponding source where required.
   Update the pinned image, package versions and timezone hash together.
3. For models, collect only read-only catalogue/show metadata. Compare the exact
   digest with the original upstream and conversion source. Retain unresolved
   issues honestly; do not classify a new digest by tag alone.
4. Run frontend generation if needed, then explicitly acknowledge reviewed input
   changes with `node scripts/licenses.mjs --record-inputs --write`.
5. Run `node scripts/licenses.mjs --check` and
   `node --test scripts/licenses.test.mjs` offline with dependencies/toolchain
   already installed. CI also checks linked dependencies for amd64 and arm64.
6. Build each release image and run
   `python3 scripts/check-license-image.py IMAGE --arch amd64` (or `arm64`).
   This inspects actual packaged files and runs the offline CLI with networking
   disabled and invalid operational configuration. It never starts the web server.

Licence inputs and notices trigger the existing image publishing workflow. The
existing SBOM output remains enabled and supplements, rather than replaces, this
notice bundle. Public downloads are allowlisted, `noindex`, and outside sitemaps;
the localized information pages themselves have canonicals, alternatives,
structured modified dates, Markdown parity and sitemap entries.

## Validation

Fresh results and screenshot links are recorded in the PR description. Tests cover
missing/changed digests, catalogue isolation, conflicting tag records, unchanged
processing availability, public/admin escaping, hostname restrictions, notice
allowlisting, multilingual SSR/Markdown, HTMX metadata and offline CLI behaviour.
Inventory failure tests cover changed inputs, tampered texts, missing references,
unreviewed components, missing compiled modules and stale generated notices.
No deployment, live mail, inference or model-account changes are part of validation.


Local results for this update: the full `go test -race ./...` suite passed
(processing 386 s, web 538 s); final focused licence tests were repeated after
metadata/download refinements. Frontend audit and govulncheck reported no
vulnerabilities. Inventory failure tests passed all eight cases. Both architecture
images passed binary/text/source/package/timezone inspection. Browser checks
found no overflow across 112 public and eight synthetic admin combinations at
320, 390, 768 and 1440 pixels in both themes. Native disclosures, visible 2px focus,
HTMX navigation/history metadata and native notice downloads were checked.
